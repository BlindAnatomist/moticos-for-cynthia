The candidate has twelve envelopes, 120 distinct pieces, twenty-four new postcard identities and seventy-two total postcard identities. The new gate collects exactly 54 cases, eighteen per profile: desktop Chromium, iPhone 13 WebKit and large-iPhone WebKit. Twelve legally earned full-discovery dense saves each retain all 100 Undo histories, load all ten collection images, and leave every source save unchanged during album browsing. Additional storage cases retain legacy migration, exact successive Undo, quota/corruption protections, provably unequal stale/winner states, and actual origin-quota behavior with synthetic 30-envelope histories.

Screenshots wait for visible images to complete actual decode and two animation frames. The gate retains actual browser version, Playwright and Node versions, profile, viewport, exact validated command and commit. Machine completion requires all expected screenshot/geometry/environment files and postcard IDs, not merely successful job summaries. Agent review of every relevant viewport and export remains required afterward.

## One-run bounds

- Proposed trigger: one push to verify/expansion-120-20261005, only after approval and a read-only branch-collision check. No PR, dispatch, wildcard push or automatic retry.
- Standard GitHub-hosted ubuntu-latest only; contents:read; run_attempt 1 only; no deployment, merge, spend or budget setting.
- One preflight job capped at 7 minutes. Three browser jobs capped at 15 minutes each. Total maximum: 52 runner-minutes; billing rounding may differ.
- Each browser profile: one worker, zero retries, stop on first failure. The command guard admits only the exact full-profile invocation. Suite budget 8–9 minutes, with 120 seconds evidence reserve plus 15 seconds scheduling margin. If startup leaves less than eight browser minutes, record incomplete without starting.
- Preflight builds once, freezes source, scenario, harness, commit and every output byte. All profile jobs restore and verify that exact build; they never rebuild.
- Maximum retained upload budget: 32 MiB preflight + 98 MiB per profile = 326 MiB. Each profile allows two complete lossless 45 MiB parts plus 8 MiB independent diagnostic salvage. Every upload is under the connector’s 200 MiB working ceiling. One-day retention, immediate parent download/readback.
- Complete source logs, journals, screenshots, traces, reports and exports are preserved even on failure where the runner still permits cleanup. Evidence overflow fails closed; no recompression, omitted files or diagnostic-only artifact can become a passing release claim. Each artifact and restored raw file must match its SHA-256 and length.
- Cancellation can prevent cleanup; that is an incomplete gate, never a pass. No automatic rerun. A new run or material scope change requires new approval.

## Performance and rollback limits

The forty new lossless WebPs total 13,172,816 bytes. All are 768×768; per-envelope image loading, decode, mobile navigation and memory remain browser measurements, not established phone-performance claims. The storage adapter preserves retained histories but does not promise cross-tab atomic compare-and-swap, browser eviction resistance or power-loss durability. A rollback after v2 storage migration must retain the decoder to resume migrated histories.

The 120-piece milestone is not a completed 300-piece game. Cynthia is not needed for routine engineering QA.
