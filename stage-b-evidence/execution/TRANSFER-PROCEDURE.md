# Verified game-source transfer procedure

This is a technical procedure, not permission to publish, spend, retry or start a workflow. Obtain explicit authority for the exact source, destination and bounded run first. Preserve any cancellation or review denial; do not switch tools or routes to evade it.

1. Verify the exact local source seal, pinned builds and game-only file manifest. Include approved game source, accepted game assets and test infrastructure. Exclude credentials, book/archive material, private research, unrelated chat, private Library identifiers and local operational evidence.
2. Read the existing remote base commit/tree and verify its identity. Reuse remote blobs only when their Git object identity matches the exact expected local bytes. Record path, mode, byte count, Git blob ID and SHA-256 for each transfer entry.
3. Upload only missing content through individually bounded blob requests. Verify each returned blob ID against the locally computed Git blob ID before using it. A partial upload is not a published branch or a completed transfer.
4. Build the tree as a bounded delta on that verified base. In the observed 200-piece transfer, a full 405-entry from-scratch tree request returned GitHub 422 with a timeout; a 92-changed-entry tree on the verified r5 base succeeded. These are observations from that transfer, not universal size limits, and do not explain every earlier approval abort. Do not infer approval to retry from a technical timeout.
5. Require the resulting final tree ID to equal the expected local tree exactly, including deletions and modes. Create the commit with accurate parent/provenance and the newly reviewed source/build identities. Verify the remote commit and tree before publishing a ref; never describe an API-created commit as the same local commit unless its hash actually matches.
6. Recheck branch absence/current head and the run ledger. Create the exact verification ref only after complete checks and explicit run authority; creating the ref can trigger Actions. Stop on unexpected remote state. No preliminary ref or duplicate publication is needed to test access.
7. Record remote commit, branch, run ID, attempt, start time, authorized start count and outcome. Monitor the approved run without automatically rerunning it. Preserve raw reports, original screenshots/postcards, collection/build proofs, manifests, hashes and acceptance or failure evidence before artifact expiry. Preserve failed/incomplete status; do not summarize it as acceptance.

No merge, deployment, security change, budget change or unapproved retry follows from this procedure. Keep private transfer credentials and private preservation identifiers in the coordinator's private records, not public repository documents.
