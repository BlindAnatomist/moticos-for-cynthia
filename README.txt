Moticos campaign browser verification proposal

Status: private preparation, no current browser acceptance. All browser cases
remain unexecuted until the owner separately authorizes the exact projection
publication and bounded run. Operator flags do not constitute authorization.

The seven independent first/return, choice, chapter, recovery, replay, race and
keyboard journeys are adopted and strengthened, with focused extra campaign
cases rather than repeating every journey across every viewport. C01 plays all
nine Garden letters through UI; C02 starts from an explicitly prepared Garden
completion and plays all seven Moon letters through UI. Other injected legal
fixtures test boundaries. Automation cannot establish uncoached understanding,
enjoyment, voluntary return, audible sound, assistive-technology usability, or
physical-device performance. There is no AAA or release-readiness claim.

Proposed scope: 14 Chromium + 7 touch-WebKit cases, one worker, zero retries,
fail on first failure. Per-case caps 25–75 seconds; Chromium group 6 minutes,
WebKit group 4 minutes; one standard ubuntu-latest job capped at 18 minutes.
A group starts only if its full budget plus 90 seconds for evidence remains.
The accepted preceding gate actually took 60.5 seconds for 8 Chromium cases and
95.7 seconds for 6 WebKit cases; its complete 9-letter UI route took 36.7 seconds.
These measured baselines justify focused bounds, not long generic timeouts.
No browser is launched during read-only collection or Node contract checks.

Artifacts: at most 23 planned original screenshots + 2 original downloaded
postcard PNGs + 1 failure screenshot, one failure trace, total 60 MiB including
manifests and hidden runner metadata. Video off. Trace screenshots, DOM/network snapshots, source files and embedded
attachments are off; original screenshots and error context remain separate.
All artifact retention is one day. If full evidence exceeds the cap or fails
validation, a separate diagnostic-only upload is bounded to2MiB. It retains
source identity, available raw reports/progress, a derived case-status summary,
and small valid failure images/error context when they fit. Every omitted file
is identified by size, hash and reason. Raw originals are never modified or
recompressed. Diagnostic-only uploads remain incomplete and fail the final gate. Original PNG streams, hashes, dimensions and
bytes are checked. No screenshot recompression or omitted failure evidence may
be used to make a failed cap look passing. Source/build and case/ledger results
must match; incomplete, skipped, flaky, changed source or excess evidence fails.

Cache coverage: two representative cache-empty/repeat/reference comparisons,
four probe encodes total. The real UI separately opens a Moon postcard, reopens
it without another encode, then opens a Garden postcard (two UI encodes). Both
actual PNG downloads are retained. The isolated probe does not measure lazy-chunk
load or physical latency; the UI supplies separate readiness observations.

Local preparation with already installed dependencies:
node --test tests/campaign-contract/*.test.mjs
./node_modules/.bin/playwright test --config=playwright.campaign.config.mjs --list --reporter=json

The exact application is copied from an explicit runtime import allowlist.
No private notes, prior review reports, conversation/call details, unrelated root
files, credentials, repository history or active workflows are included.
The inert workflow proposal targets only a future authorized push to
BlindAnatomist/moticos-for-cynthia, branch verify/campaign-20261007, first run
attempt. It requires no main/default-branch workflow change or merge.

No external upload, publication, install, spending or CI action is authorized by
this document. If a zero-dollar spending stop blocks an authorized run, stop and
notify the owner; never change budgets, disable the stop or enable paid overages.

Repair-v3 evidence policy
All modal actions are scoped to the active dialog and their actual container.
Collection buttons use exact accessible names, with exact-one guards. Each
actual postcard download is journaled immediately, so a later failed UI step
cannot discard a valid partial export.
Only unfinalized Playwright recorder *.trace/*.network working files under the
exact hidden recorder directory are excluded from upload. Their hashes, sizes
and omission reasons are retained; raw files remain untouched. Canonical final
trace.zip, screenshots, error context, raw results, progress and runner metadata
remain eligible. This does not alter the60MiB cap or make an incomplete run pass.

Repair-v4 candidate (pending independent review)
Responsive classification waits for exactly one rendered mobile HUD or desktop
progress surface after reload, using the existing action timeout. It does not
infer desktop from a mobile control that has not appeared yet.
The evidence policy additionally excludes only direct, 32-lowercase-hex GUID
PNG files in campaign-{chromium,webkit-phone}/raw/.playwright-artifacts-N/ when
both readable raw reports contain no attachment with that basename.
Missing/malformed reports, referenced images and unknown paths remain eligible.
Content duplication is not an exclusion criterion. The same eligibility function
is used for byte sizing, full verification and upload copying; every exclusion
records the original path, byte size, SHA-256 and reason in the omission ledger.
Canonical failure PNG and final trace attachments must be present for an observed
failure. All original bytes and existing caps are retained. Diagnostic fallback
remains incomplete. No final source seal or browser acceptance is asserted here.
